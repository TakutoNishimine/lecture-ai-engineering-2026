### トークン数表示の実装

`response.usage_metadata.prompt_token_count` を入力、`candidates_token_count` を出力として表示した。メタデータや個別の値が返らない場合は「未取得」と表示し、ゼロとは区別した。出力はSDKが返した候補のトークン数であり、推論等を含めた総使用量を示すものではない。

## 宿題

- 取り組んだレベル：**実装**
- やったこと：`app/ask.py` に `--chat` オプションを追加し、会話履歴を保ったまま続けて質問できるようにした。
- 使ったモデル：`gemini-3.5-flash-lite`

### 実装の仕組み

1. `client.chats.create(model=MODEL)` で会話を1回だけ作成する。
2. 入力を繰り返し受け取り、同じ `session.send_message(question)` に送る。Google SDKが過去の質問と回答を次のリクエストに含める。
3. 各回答と、その時点の入力・出力トークン数を表示する。
4. 空行・`/exit`・`/quit`・入力待ちのCtrl+D/Ctrl+Cで終了する。
5. 履歴はプロセスのメモリ内だけに保持する。終了後は残さない。従来の `--chat` なしの1回だけの質問も利用できる。

### 実際の会話で確認した結果

```bash
uv run python -m app.ask --chat "私の好きな色は青です。短く覚えたと答えてください。"
```

| 順序 | 質問・操作 | 実際の回答 | 入力 / 出力トークン数 |
|---|---|---|---|
| 1 | 私の好きな色は青です。短く覚えたと答えてください。 | 覚えた。 | 16 / 3 |
| 2 | 私の好きな色は何でしたか？短く答えてください。 | 青です。 | 34 / 3 |
| 3 | /exit | 会話を終了しました。 | API呼び出しなし |

2回目の質問自体には「青」という情報が含まれていないが、前の発言を踏まえた回答が返った。入力トークン数も16から34に増えた。ただし、トークン数の増加だけで履歴保持を証明したわけではなく、以下のテストでも送信内容を確認した。

### 気づき・疑問

- 会話を続けるには、毎回新しいチャットを作らず、同じ会話オブジェクトを使う必要がある。
- 履歴を持つことで直前の発言を参照できるが、講座固有の知識が自動的に追加されるわけではない。
- 会話が長くなると過去の内容も入力に含まれるため、入力トークン数や利用枠への影響が大きくなる。今回は長い会話での上限や複数モデルの比較は行っていない。
- 長い会話では履歴の要約や削除をどう行うかが次の検討課題になる。
